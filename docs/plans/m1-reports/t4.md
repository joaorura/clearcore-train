# M1 Tarefa 4 — Caminho até 16 kHz e validação do enrollment

Branch `m1/t4` (worktree `clearcore-train-wt/m1t4`).

## O que foi feito
- `data/resample.py`: `to_16k(x, sr)`. 16 kHz = cópia; 48 kHz = `resample_48k_to_16k` (v1, bit-exato); demais SR = soxr HQ
  (`data.audio.resample`) -> 48 kHz -> filtro v1. Recusa não-1-D e `sr` não inteiro positivo. Coeficientes e goldens do v1
  intocados (`git status resampler` limpo; testes bit-exatos do v1 seguem verdes).
- `data/enroll.py` (novo): `validate_enrollment_audio(x16k) -> None` (levanta `EnrollmentRejected(ValueError)` com
  `.reason`/`.value`) e `check_enrollment_audio` (devolve `EnrollmentReport`). Réplica exata de
  `crates/model/src/enrollment.rs`: mesmas constantes, mesma ordem das checagens, soma f64 sequencial, dB convertido para
  f32, limiares/comparações em f32.
- Paridade contra o Rust: `scripts/enroll_validate_ref.rs` (cópia reduzida a std das funções do Clearcore, commit 818e7ce
  do checkout local) compilada com rustc 1.90.0 por `scripts/gen_enroll_validation_golden.py`, que roda os 31 casos de
  `tests/enroll_cases.py` e grava `tests/golden/enroll_validation_v1.json`. Os testes comparam decisão, motivo e medidas
  (peak, rms_dbfs, fração ativa) bit a bit em f32. Casos de borda: 95999/96000/192000/192001 amostras, vazio, NaN/±inf (e
  precedência sobre duração/clipping), pico 0.99 exato vs próximo f32, DC 0.01 (-40.0 após cast f32: recusa), fração 179/180
  de 300 quadros, limiar relativo -30 dB ±0.1%, cauda parcial de quadro, sinais tipo fala.
